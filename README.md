# Lumo — смотри шире

Видеоплатформа с собственным дизайном: **React + Vite + Tailwind CSS** на frontend,
Node.js + Express + PostgreSQL + Prisma на backend.

## Открыть сайт

Нужны **Node.js 24 LTS** и npm. Для демонстрационного интерфейса Docker и база не нужны.
Если проект уже скачан, выполните в его папке:

```bash
git pull origin main
npm ci
npm run dev
```

При первом скачивании:

```bash
git clone https://github.com/Boboduk/test.git
cd test
npm ci
npm run dev
```

Откройте **http://localhost:5173**. Оставьте терминал открытым.
Для остановки нажмите `Ctrl+C`. Если порт занят, остановите предыдущий процесс.

**Важно:** `npm run dev` теперь запускает React-сайт на порту 5173.
Команда для backend — `npm run dev:backend`; он слушает порт 4000 и возвращает JSON.

## Возможности frontend

- Адаптивная главная, боковое меню и девять карточек видео.
- Поиск по названиям, авторам и тегам с автодополнением; категории и сортировка.
- HTML5-плеер: воспроизведение, перемотка, скорость и полноэкранный режим.
- Каналы, рекомендации, подписки, «Смотреть позже», история и реакции.
- Добавление и удаление собственных локальных комментариев.
- Просмотр видео с компьютера без отправки на сервер.
- Светлая и тёмная темы; управление с клавиатуры, уменьшение анимаций.

Это **демонстрационный frontend**. Названия, каналы и статистика — примеры.
В плеере воспроизводятся оригинальные 8-секундные анимации без звука (720p).
Иллюстрации и видео включены в репозиторий, внешние CDN не требуются.
Исходник генератора: `apps/frontend/scripts/generate-demo.py`; для запуска сайта
Python и FFmpeg не нужны.

Личные списки и комментарии сохраняются в `localStorage` этого браузера.
Очистка данных браузера удаляет их; синхронизации между устройствами пока нет.
История записывается при запуске видео, а не при открытии страницы.
Регистрация, JWT, серверная публикация и настоящие социальные API ещё не реализованы.
Интерфейс не выдаёт локальный просмотр файла за публикацию на сервере.

## Структура

```text
apps/
  frontend/
    src/
      components/    # Карточки, аватары, диалоги
      pages/         # Ленты, каналы, просмотр
      test/          # Проверки пользовательских сценариев
      App.tsx        # Маршруты, меню, поиск
      data.ts        # Демо-коллекция
      storage.ts     # Локальные списки
      styles.css     # Tailwind и оформление
    public/
      covers/        # Оригинальные SVG
      media/         # Готовые MP4
    scripts/         # Генератор демо-материалов
  backend/
    prisma/          # Схема PostgreSQL
    src/             # Express, настройки, Prisma
    tests/           # HTTP-тесты
compose.yaml         # Локальный PostgreSQL
```

## Backend (отдельный терминал)

Нужен работающий Docker с Compose либо собственный PostgreSQL 17.
Если backend уже запущен, повторно запускать его не нужно.

Следующий блок — для первого запуска с новой базой. При последующих запусках
достаточно `docker compose up -d --wait` и `npm run dev:backend`.
Повторно копировать `.env` и создавать начальную миграцию не нужно.

```bash
cp -n apps/backend/.env.example apps/backend/.env
docker compose up -d --wait
npm run db:generate
npm run db:migrate -- --name init
npm run dev:backend
```

В PowerShell, только если `.env` ещё нет:

```powershell
Copy-Item apps/backend/.env.example apps/backend/.env
```

В облачной среде используйте существующий checkout `/workspace/test`.
Не создавайте отдельный Git worktree, если пользователь явно этого не запросил.
Существующий `.env` не перезаписывайте. Первая миграция создаётся командой
`db:migrate`; сохраните созданные SQL-файлы в Git. Когда миграции уже сохранены,
на новых машинах применяйте `npm run db:deploy`.

### Если команда не запускается

Вводите `npm run dev:backend` без точки в конце. Команда `npm run dev:backend.`
ищет другой npm-скрипт, которого нет.

Если Prisma сообщает, что миграция применена к базе, но отсутствует локально,
восстановите исходную папку этой миграции вместе с `migration.sql` в
`apps/backend/prisma/migrations` из предыдущей копии проекта, Git или резервной копии.
При обновлении проекта ZIP-архивом Docker volume сохраняет базу и её историю,
а локальные файлы миграций могут потеряться. Если исходных файлов нет, восстановление
истории нужно разбирать отдельно; не создавайте фиктивный SQL с тем же именем.
Не запускайте `prisma migrate reset` и не удаляйте volume для устранения этого сообщения:
это уничтожит данные. До восстановления истории не выполняйте новые миграции.
Сам frontend запускается командой `npm run dev` и не требует базы.

Пример `apps/backend/.env`:

```dotenv
NODE_ENV=development
HOST=127.0.0.1
PORT=4000
DATABASE_URL=postgresql://lumo:lumo_local@127.0.0.1:5432/lumo?schema=public
FRONTEND_ORIGIN=http://localhost:5173
```

Пароль предназначен только для локальной разработки и соответствует `compose.yaml`.
Файл `.env` исключён из Git. Для production нужны собственные учётные данные.
Vite перенаправляет `/api` на `http://127.0.0.1:4000`.
В окне «О демо-профиле» можно проверить backend и подключение к базе.

```bash
curl --fail http://127.0.0.1:4000/api/v1/health/live
curl --fail http://127.0.0.1:4000/api/v1/health/ready
```

`ready` выполняет SQL-запрос и отвечает `{"status":"ok","database":"connected"}`.
Это подтверждает подключение, но не наличие API публикации и авторизации.

## Сборка и проверки

```bash
npm run build:frontend
npm run preview
```

Предпросмотр собранного сайта также использует порт 5173; сначала остановите dev-сервер.
Это локальный просмотр production-сборки, а не публичный хостинг.

```bash
npm test
npm run build
npm run db:validate
npm run db:smoke
```

`npm test` проверяет оба приложения. `npm run build` собирает оба приложения;
для генерации Prisma нужны `apps/backend/.env` и HTTPS-доступ к `binaries.prisma.sh`.
`db:smoke` требует PostgreSQL с применёнными миграциями и откатывает временные данные.

Для размещения frontend используйте `apps/frontend/dist`.
Хостинг должен перенаправлять неизвестные пути вроде `/watch/mountains` на
`index.html` (SPA fallback). Для реального API отдельно настройте reverse proxy
на backend. Сборка проекта не публикует сайт автоматически.

## Остановка базы

```bash
docker compose stop
```

Данные остаются в Docker volume. После перезапуска машины процессы frontend,
backend и контейнер базы нужно запускать заново.
