# Lumo — видеохостинг

Этап 1 реализации: основа backend на Node.js, Express, TypeScript и PostgreSQL через Prisma.
Frontend и пользовательские API будут добавлены на следующих этапах.

## Что уже работает

- Проверка настроек при запуске без вывода секретных значений.
- Express с Helmet, CORS и единым форматом ошибок.
- Схема БД: пользователи, сессии, видео, варианты качества, теги, реакции,
  комментарии, подписки, история и «Смотреть позже».
- Скрипт проверки реальных связей PostgreSQL после применения миграций.
- Проверки процесса и подключения к БД.

Регистрация, JWT, загрузка видео и остальные продуктовые маршруты пока не реализованы.

### Состояние проверки в облачной среде

PostgreSQL запущен, HTTP-тесты проходят. Генерация клиента и проверка схемы Prisma
пока заблокированы сетевой политикой: официальный `binaries.prisma.sh` отвечает 403
на запрос движка миграций. Разрешение домена сохранено в черновике среды;
сохранение черновика не применяет политику и не публикует среду.
Начальная миграция ещё не создана, проверка `db:smoke` и запуск полного сервера
ожидают генерации Prisma. Проверки TLS и контрольных сумм не отключались.

## Требования

- Node.js 24 LTS и npm (версия Node также указана в `.nvmrc`).
- Docker с Compose либо PostgreSQL 17, запущенный самостоятельно.

## Установка

Команды выполняются из корня репозитория. В облачной среде используйте существующий
checkout `/workspace/test`; отдельный Git worktree создавать не требуется.

```bash
cd /workspace/test
npm ci
cp -n apps/backend/.env.example apps/backend/.env
docker compose up -d --wait
npm run db:generate
npm run db:migrate -- --name init
npm run dev
```

При локальном клонировании замените `/workspace/test` на путь к проекту.
`cp -n` сохраняет уже существующий `.env`. Файл с локальными значениями исключён из Git.
На текущем этапе `db:migrate -- --name init` создаёт и применяет начальную миграцию.
После добавления этой миграции в Git на новых машинах используйте `npm run db:deploy`.

Пример `apps/backend/.env`:

```dotenv
NODE_ENV=development
HOST=127.0.0.1
PORT=4000
DATABASE_URL=postgresql://lumo:lumo_local@127.0.0.1:5432/lumo?schema=public
FRONTEND_ORIGIN=http://localhost:5173
```

Пароль в примере предназначен только для локального контейнера PostgreSQL,
порт которого привязан к loopback. Для production задайте отдельные учётные данные.
`FRONTEND_ORIGIN` указывается без завершающего слеша. JWT-настройки появятся вместе
с модулем авторизации; сейчас сервер не выдаёт токены.

## Проверка

В другом терминале:

```bash
npm run db:validate
npm run build
npm test
npm run db:smoke
curl --fail http://127.0.0.1:4000/api/v1/health/live
curl --fail http://127.0.0.1:4000/api/v1/health/ready
```

Проверка `live` возвращает `{"status":"ok","service":"lumo-api"}`.
Проверка `ready` выполняет SQL-запрос и возвращает
`{"status":"ok","database":"connected"}`. При потере подключения она отвечает 503.
Проверка `db:smoke` создаёт временные записи, проверяет связи и каскадное удаление,
затем откатывает транзакцию, не оставляя тестовых данных.

Для запуска собранного backend:

```bash
npm run build
npm start
```

## Изменение схемы

```bash
npm run db:migrate -- --name название_изменения
npm run db:generate
```

Созданные SQL-миграции сохраняйте в Git. На этапе пользовательских API добавим
ограничение подписки на себя и поисковые индексы отдельной миграцией.
Счётчики `BigInt` при реализации API нужно преобразовывать в строки перед JSON-сериализацией.
Ограничение ответов одним уровнем будет проверяться сервисом комментариев.

## Остановка

Сервер останавливается через `Ctrl+C`, закрывая HTTP-соединения и клиент Prisma.

```bash
docker compose stop
```

Данные PostgreSQL сохраняются в Docker volume. После перезапуска облачной машины
заново запустите контейнер и backend: работающие процессы не сохраняются.
